# かかる日数の基準

> `10-standard-tasks.md` に書いた標準作業ごとに、どれくらいかかるかを書く。
> 正確な値を出そうとしない。**過去に1回やったときの実感**でよい。ずれていたら後から直す。
> 記入したら、この引用ブロックは削除する。

## 1. 標準作業ごとの標準工数

「標準」規模を基準にした既定値。

| 標準作業 | 標準工数 | 上限側を採る条件 |
|---|---|---|
| | | |
| | | |
| （予備日） | 0人日 | 標準作業ではない。量と位置は第4章 |

**書くのは工数（人日）だけ。所要日数（カレンダー上の長さ）はここに書かない。**
所要日数は `40-team.md` の人数と実働係数から式で出す（`definitions/20-scheduling-rules.md` 第2章）。
両方を書くと、必ずどちらかが式と合わなくなる。

```
有効人数 = 1 + (人数 − 1) × 0.7
所要日数 = ceil( 工数(人日) / (有効人数 × 実働係数) )
```

**範囲で書いた場合は「上限側を採る条件」を必ず埋める。** 空だと毎回違う値が出る。

### 変更時の影響

- 標準工数を増やすと、その作業を含むすべてのスケジュールの期間が伸びる。
  期日が固定されている案件では、前倒しで着手する日程が出るか、範囲を削るリスク記述が増える。
- 実働係数の低い役割（0.4 など）では、工数を少し増やしただけで所要日数が上限（15稼働日）を超え、
  タスクが2本に分割される。分割の仕方は `20-scheduling-rules.md` 第2章にある。

## 2. 規模による倍率

| 規模 | 倍率 |
|---|---|
| 小さい | 0.5 |
| 標準 | 1.0 |
| 大きい | 1.5〜2.0 |

**倍率は工数に掛ける。** 所要日数には掛けない（第3章と同じ）。

## 3. 条件による倍率

> 「これが当てはまると余計に時間がかかる」という条件を挙げる。

| 条件 | 倍率 |
|---|---|
| 前例がない（初めてやる進め方・初めて使う相手や道具） | 1.3 |
| | |

**倍率は工数（`effortDays`）に掛ける。所要日数には掛けない。**
複数該当する場合は掛け合わせる。

```
工数 = 標準工数 × 規模倍率 × 条件倍率（掛け合わせ）
所要日数 = ceil( 工数 / (有効人数 × 実働係数) )   ← 端数の切り上げは最後に1回だけ
```

倍率を適用したタスクがある場合、そのことを `task.notes` に書き、`risks[]` にも1件記録する。

### 変更時の影響

- 倍率を上げると、その条件に当てはまる案件だけ期間が伸びる。
  特定の種類の案件で見積もりが甘いと感じたときは、標準工数ではなくこちらを調整するほうが副作用が小さい。
- 掛け先を所要日数に変えると、切り上げが2回入って結果が変わる。掛け先は工数で統一する。

## 5. 並行してよい組み合わせ

**この章のすべての行に、次の2つが先に効く。**

| 先に効く決まり | 内容 |
|---|---|
| **同じ役割のタスクは重ねない** | 並行してよい組み合わせであっても、**担当が同じ役割なら直列に置く**（`40-team.md` 第2章）。**人数を増やしても重ねられない** |
| 同時本数の上限 | 同時に走らせられる作業本数を超えない（`40-team.md` 第2章） |

そのうえで、並行してよい組み合わせを書く。

| 先に進むもの | 並行して進めてよいもの | 着手のタイミング |
|---|---|---|
| | | |

並行は `SS` + `lagDays` で表す。既定のずらし幅は先行タスクの所要日数の 50%。

**並べたあとに前後が逆転していないか確認する。** ずらし幅を大きく取ると、
後のタスクが先のタスクより先に終わる並びが作れてしまう。
**後のタスクの開始日は先行タスクの開始日より前に置かない。終了日も先行タスクの開始日より後にする。**

## 7. 同じ作業が繰り返し出るとき

> 1つのフェーズの中に同じ標準作業が2回以上出ることがある。
> （面接を2回やる、機能A・機能B・機能Cのそれぞれに要件定義を置く、など）
> **2回目以降は1回目より軽くなる。** 進め方が分かっていて、判断の材料も揃っているため。

| 何回目か | 工数に掛ける係数（既定） |
|---|---|
| 1回目 | 1.0 |
| 2回目 | 0.7 |
| 3回目以降 | 0.5 |

| 決めること | 決まり |
|---|---|
| 下限 | 0.5人日を下回らない |
| 数える範囲 | **同じフェーズの中**。フェーズが変われば1回目に戻す |
| 同じにならない場合 | 対象の大きさが回ごとに大きく違うなら、係数を使わず個別に見積もる |
| 記録 | 係数を適用したことを `meta.assumptions` に1行残す |

**この章を空のままにすると、2回目以降も1回目と同じ工数で積まれ、全体が長く出る。**

### 変更時の影響

- 係数を 1.0 に戻すと、繰り返しの多い用途（採用、複数機能の開発）で期間が目に見えて伸びる。
- 下限を外すと、4回目以降が 0 に近づき、実際には必ずかかる時間が計画から消える。
