# 標準作業

受託案件の進行管理で繰り返し出てくる作業の型。ここに書いた内容は**生成時に参照するだけ**で、出力される JSON には作業の名前しか残らない。

版 6.0 でタスク種別を削除したため、このファイルは種別の語彙表ではなく、標準作業の一覧になった。
以前の内容は `_archive/definitions/presets/client-project/10-task-types_v5.0_2026-09-06.md` にある。

## 1. 標準作業の一覧

| 標準作業 | 既定の担当役割 | 並行可否 | 増員が効くか | 説明 |
|---|---|---|---|---|
| ヒアリング | 営業窓口 | 直列 | 効く | 要望と条件を聞き取る |
| 見積 | 進行管理 | 直列 | **効かない** | 範囲を確定し、金額と期間を出す |
| 契約 | 営業窓口 | 直列 | **効かない** | 条件を書面にし、締結する |
| 制作 | 制作 | 並行可 | 効く | 成果物を作る |
| 社内確認 | 進行管理 | 並行可 | 効く | 提出前の自主確認 |
| **取引先の確認待ち** | **（付けない）** | 直列 | **効かない** | 相手の確認・承認を待つ。こちらでは短縮できない。**工数は常に 0** |
| 納品 | 進行管理 | 直列 | 効く | 成果物を引き渡す |
| 請求 | 営業窓口 | 直列 | 効く | 請求書の発行と送付 |

**検収は「取引先の確認待ち」として表す。** 取引先が行う作業であり、こちらの工数は 0 だが期間は消費するため。

**「増員が効かない」作業には、所要日数の計算で人数を掛けない**（`40-team.md` 第1章）。

- 取引先の確認待ち — 相手の作業なので、こちらの人数は無関係。**工数は常に 0 とし、担当も付けない**
- 契約 — 書面のやりとりが直列
- 見積 — 判断が1人に集約される

**「取引先の確認待ち」と予備日は別物。** どちらも工数 0 で担当を付けないが、意味が違う。

| | 取引先の確認待ち | 予備日（バッファ） |
|---|---|---|
| 何か | **必ず発生する待ち時間** | 遅れたときのための余裕 |
| `isBuffer` | **`false`。普通のタスク** | `true` |
| 削ってよいか | **削れない。** 削ると実態より短い日程が出る | 状況によっては縮めてよい |
| ガント上 | 普通のバー | 斜線 |

## 2. 予備日（バッファ）

| 項目 | 値 |
|---|---|
| 表し方 | `isBuffer: true` |
| 工数 | 0人日 |
| 担当役割 | 付けない |
| 名前 | 何のための予備かが分かる名前にする（例:「制作予備日」「納品前予備日」） |

置く量と位置は `30-estimation.md` 第3章にある。

## 3. 作業名の付け方

**画面に出るのは作業の名前だけ**なので、名前だけで意味が通る必要がある。

| 場面 | 付け方 | 例 |
|---|---|---|
| 工程を挟む形 | 工程名が上の行に出ているので、対象を繰り返さない | 工程「制作」の下に「初稿の制作」 |
| 取引先の確認待ち | **何を待っているかを名前に含める** | 「見積の確認待ち」「初稿の検収待ち」 |
| 同じ作業が複数回出る | 回次や対象で区別する | 「初稿の制作」「修正稿の制作」 |

**「取引先の確認待ち」という名前をそのまま使わない。** 何を待っているのか分からない行が複数並ぶことになる。

---

## 変更時の影響

- 「取引先の確認待ち」を削ると、相手待ちの期間が計画から消え、実態より短い日程が出る。**この作業は残す。**
- 「制作」を細かく割ると制作の中身が見えるようになるが、このプリセットの狙い（取引の流れを追うこと）からは外れる。細かく見たい場合はスケジュールを2本に分ける。
- 標準作業を足したら、`30-estimation.md` 第1章に標準値の行も足す。
