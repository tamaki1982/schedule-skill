# この用途ならではの注意点

## 1. 自分たちで縮められない期間

| 何を待つか | 目安の期間 | 短縮できるか |
|---|---|---|
| 見積の確認 | 5稼働日 | できない |
| 契約書の確認・押印 | 10稼働日 | できない。先方の決裁の階層数で伸びる |
| 中間の確認・フィードバック | 3〜5稼働日 | できない。確認する日を事前に押さえておくと短くなる |
| 検収 | 10稼働日 | できない。契約に定めがあればその日数 |
| 入金 | 契約の支払サイトによる | できない |

**これらは必ず 「取引先の確認待ち」 の独立したタスクとして置く。** 制作タスクの中に埋め込まない。
埋め込むと、遅延の原因が自分たちなのか相手なのかが分からなくなる。

## 2. 後ろ倒しができない日

| 何 | なぜ動かせないか |
|---|---|
| 契約書に記載した納品期日 | 遅れると契約違反になる |
| 請求の締め日 | 逃すと入金が1か月後ろへずれる |

**請求の締め日は特に見落としやすい。** 納品が締め日の直前になる計画では、検収が間に合わず入金が1か月遅れる。
納品期日は、締め日から検収期間を引いた日より前に置く。

## 3. 見落としやすい作業

- 見積の前提条件の明記（後から範囲の認識違いが出る）
- 契約書に記載する成果物の定義
- 検収の合否判定の基準をあらかじめ合意しておくこと
- 納品物の受領書の回収
- 追加発注が発生したときの契約の扱い

## 4. この用途で必ず記録するリスク

| 状況 | 記録する内容 |
|---|---|
| 納品期日が契約で固定されている | バッファの残量と、差し戻しを何回まで見込んでいるか |
| 検収の判定基準が未合意 | 検収が長引いた場合に請求がいつまでずれるか |
| 初めての取引先 | 確認のリズムが読めないこと |
| 納品が請求の締め日に近い | 入金が1か月ずれる可能性 |

---

## 変更時の影響

- 第1章の日数を短くすると全体の期間が縮むが、相手が守れなければそのまま遅延になる。
