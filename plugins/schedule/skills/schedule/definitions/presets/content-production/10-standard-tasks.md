# 標準作業

コンテンツ制作で繰り返し出てくる作業の型。ここに書いた内容は**生成時に参照するだけ**で、出力される JSON には作業の名前しか残らない。

版 6.0 でタスク種別を削除したため、このファイルは種別の語彙表ではなく、標準作業の一覧になった。
以前の内容は `_archive/definitions/presets/content-production/10-task-types_v5.0_2026-09-06.md` にある。

## 1. 標準作業の一覧

| 標準作業 | 既定の担当役割 | 並行可否 | 増員が効くか | 説明 |
|---|---|---|---|---|
| 企画 | 企画 | 直列 | 効く | 何を作るかを決める |
| 取材・調査 | 構成 | 並行可 | 効く | 素材と情報を集める |
| 台本・構成 | 構成 | 直列 | **効かない** | 中身の設計。ここが動くと後続すべてが動く |
| 出演・取材先調整 | 制作進行 | 並行可 | **効かない** | 相手の日程を押さえる。こちらでは短縮できない |
| 収録・撮影 | 制作進行 | 直列 | **効かない** | 素材を作る。日付が固定されやすい |
| 編集 | 編集 | 直列 | 効く | 素材を作品にする |
| 確認 | 企画 | 並行可 | 効く | 内容の確認と修正指示 |
| 公開 | 制作進行 | 直列 | 効く | 公開作業と告知 |

**「増員が効かない」作業には、所要日数の計算で人数を掛けない**（`40-team.md` 第1章）。

- 台本・構成 — 中身の設計は分担しづらい
- 収録・撮影 — 収録の時間そのものは人数で割れない
- 出演・取材先調整 — 相手の都合待ちが支配的

**「出演・取材先調整」は所要日数と工数が大きく乖離する。** 手を動かす時間は短いが、相手の返事を待つ期間が長い。
`30-estimation.md` の標準値もその形で置いてある。

## 2. 予備日（バッファ）

**予備日は標準作業ではない。** 遅延を吸収するための空き時間であり、作業ではないため。

| 項目 | 値 |
|---|---|
| 表し方 | `isBuffer: true` |
| 工数 | 0人日 |
| 担当役割 | 付けない |
| 名前 | 何のための予備かが分かる名前にする（例:「編集予備日」「公開前予備日」） |

置く量と位置は `30-estimation.md` 第3章にある。

## 3. 作業名の付け方

**画面に出るのは作業の名前だけ**なので、名前だけで意味が通る必要がある。

| 場面 | 付け方 | 例 |
|---|---|---|
| 工程を挟む形 | 工程名が上の行に出ているので、対象を繰り返さない | 工程「編集」の下に「粗編集」 |
| 工程を挟まない形（3本を超える連載） | **回次を名前の先頭に置く** | 「第1話 台本・構成」「第1話 収録・撮影」 |
| 同じ作業が1つのフェーズに複数出る | 何についての作業かで区別する | 「導入部の編集」「本編の編集」 |

---

## 変更時の影響

- 行を追加・削除すると、生成されるスケジュールに出てくる作業が増減する。**出力の形は変わらない**（標準作業は JSON に載らないため）。
- 「編集」を「粗編集」「仕上げ」に割ると、確認を挟むタイミングが計画に載るようになる。
- 標準作業を足したら、`30-estimation.md` 第1章に標準値の行も足す。
