# プリセット: ソフトウェア開発

| 項目 | 値 |
|---|---|
| id | `software-development` |
| 表示名 | ソフトウェア開発 |
| 版数 | 2.1 |
| 最終更新 | 2026/09/07 |

ソフトウェアを新しく作る、既存のものに機能を足す、作り直す、といった依頼のためのプリセット。
このツールで最初に整備した用途であり、他のプリセットより作り込んである。

---

## 1. こういう依頼のときに使う

- 「機能を追加する」「画面を作る」「システムを作り直す」といった依頼
- 動くソフトウェアを作って公開するところまでが範囲に含まれる
- 「実装」「テスト」「リリース」「デプロイ」といった言葉が入力文に出てくる
- 対象が自社のプロダクトや社内システムで、進め方を自分たちで決められる

## 2. こういう依頼には使わない

| こういう場合 | 使うプリセット |
|---|---|
| 取引先から請けた開発で、見積・契約・検収・請求まで含める | `client-project` |
| 開発は伴わず、告知や当日運営が中心 | `event-campaign` |
| 動画・記事・楽曲などの制作が中心 | `content-production` |

取引先案件でも、契約が済んでいて制作だけを管理したい場合はこのプリセットでよい。

---

## 3. 前提

- 実行環境は既存のものを流用でき、ゼロから調達する必要はない
- 開発に使う技術は、一部の新規要素を除いて経験があるものである
- 検証は自分たちで行い、第三者機関の審査は挟まない
- 公開後の運用・監視の体制はすでにある

上記に当てはまらない案件では、該当する内容を `meta.assumptions` に書き換えて記録する。

---

## 4. このプリセットのファイル

| 順 | ファイル | 決めていること |
|---|---|---|
| 1 | `10-standard-tasks.md` | 出てくる標準作業（11件） |
| 2 | `20-structure.md` | 規模別の標準構成 |
| 3 | `30-estimation.md` | 標準作業ごとの標準日数、倍率、予備日の量、並行してよい組み合わせ |
| 4 | `40-team.md` | 役割ごとの人数と実働係数、同時並行の上限 |
| 5 | `50-domain-notes.md` | この用途特有の注意点 |

---

## 変更時の影響

- 「こういう依頼のときに使う」を書き換えると、どの依頼でこのプリセットが選ばれるかが変わる。
- 版数を上げると、生成結果の `meta.preset.version` に記録される値が変わる。
