# スケジュール作成ツール

自然文の依頼からスケジュールを組み立てるツールです。「11月中にリリースしたい」と伝えると、
工程とタスクに分解し、営業日を数えて日程を置きます。
出来上がるのは**ガントチャート1枚の HTML ファイル**で、外部のファイルを一切参照しません。
そのファイルを送れば、受け取った人がブラウザで開くだけで同じものが見られます。

---

## 導入手順

1. **人がやること**: このフォルダ（`schedule` スキル一式）を、Claude Code のプラグイン経由で
   インストールする。手順は配布リポジトリの `README.md`（`/plugin marketplace add` と
   `/plugin install`）を参照。
2. **AI がやること**: 初回にスケジュールを作るとき、AI が生成物と自分用の設定ファイルの
   置き場所（以下「置き場」）を確認する。候補が1つ提示されるので、そのままでよければ承認する。
   別の場所にしたい場合は伝える。
3. 決めた置き場は `CLAUDE.md` に記録され、次回以降は聞かれない。**置き場はこのフォルダ（スキル本体）
   とは別の場所になる。** スキルを更新・再インストールしても、作ったスケジュールや自分用に
   書き換えた設定ファイルは影響を受けない。

**正しく置けたかの確かめ方**: 置き場のフォルダの中に `definitions/`（自分用にコピーされたもの）
ができていれば設定は済んでいる。まだスケジュールを1本も作っていなければ `output/` はまだ無い
（最初の1本を作ったときにできる）。

---

## 最初の1本を作る

1. このフォルダを開いた状態で、AI に作りたいスケジュールを伝えます。
2. 情報が足りないとき、または置き場がまだ決まっていないときは聞き返されるので、答えます。
3. 置き場の `output/` の中に HTML と JSON が対で出ます。
4. **HTML をブラウザで開きます。** これが出来上がったスケジュールです。

### 伝え方の例

```
社内ポータルにバーチャルオフィス機能を追加する。
11月中にリリースしたいので、逆算してスケジュールを作って
```

```
10/25 のユーザー向けイベントの準備スケジュールを作って。
告知は9月の頭から始めたい
```

```
受託案件を来週から着手して年内納品。工程表を引いて
```

### 一緒に伝えておくと精度が上がるもの

| 伝えること | 例 |
|---|---|
| いつまでに | 「11月中に」「年内に」「12/11 に公開」 |
| いつから | 「来週から」「年明けから」 |
| 体制 | 「実装は2名」「ひとりでやる」 |
| すでに決まっている日 | 「本番は 11/22（日）」 |
| 入れたい・要らない作業 | 「セキュリティ確認を入れて」「リハーサルは不要」 |

指定が無いものは推定して組み立てられ、**何をどう推定したかは生成結果に残ります。**

---

## 作ったものを直す

日程をずらす、作業を足す、担当を変える、完了にする。
いずれも**AI に言うのがいちばん軽い経路**です。画面の上で直すこともできます。

**やり方と言い方の実例は `HOW-TO-REVISE.md` にまとめてあります。**

---

## 自分のやり方に合わせる

このツールの判断基準は、すべて **置き場にコピーされた** `definitions/` の中の Markdown ファイルに
書いてあります。コードの中に基準は入っていません。**ここを書き換えるだけで、次に作るものが変わります。**
（このフォルダ内の `definitions/` は配布時点の既定値であり、書き換えても効きません）

| やりたいこと | 開くファイル |
|---|---|
| 自分の組織のやり方に合わせたい（稼働日、目標日への向き合い方、作業の束ね方、呼び方） | `<置き場>/definitions/50-user-context.md` |
| 自分の分野を足したい（どんな作業が出てくるか、どれくらいかかるか、誰がやるか） | `<置き場>/definitions/90-how-to-add-preset.md` の手順に従って `<置き場>/definitions/presets/` にフォルダを足す |

**まず `<置き場>/definitions/00-index.md` を読んでください。** どのファイルが何を決めているか、
どれを書き換えてよくてどれを書き換えないかが、そこに書いてあります。

書き換えは AI に頼めます。「見積もりを全体に1.2倍にして」「稼働は月〜木の週4日にして」のように伝えると、
該当するファイルが直されます。

**書き換えても、すでに出来上がっている資料は変わりません。** 次に作るものから効きます。

## 困ったときは

**このツールの仕様についての質問は、そのまま AI に聞いてください。**
`FAQ.md` に答えを用意してあり、AI はそれを読んで答えます。

よくある質問の例:

- 画面で直した内容はどこへ行くのか
- 書き出したファイルをどうすればいいか
- 目標日に間に合わないときはどうなるのか
- 印刷はできるのか

## フォルダの中身

**このフォルダ自体は「スキル本体」であり、生成物は置かない。** 生成物と自分用の設定ファイルは、
導入時に決めた「置き場」（このフォルダとは別の場所）に入る。

| 場所 | 何が入っているか | 書き換えるか |
|---|---|---|
| `definitions/` | 判断基準の**配布時点の既定値**。階層・日程・出力の決まりと、用途ごとのプリセット | **書き換えない。** 自分用に書き換えるのは置き場にコピーされた方 |
| `schema/` | データの形と、動作するサンプル2本 | 書き換えない |
| `templates/` | 出力の器と、検証・書き出しの処理 | 書き換えない |
| `SKILL.md` | AI が読む作り方の指示書 | 書き換えない |
| `HOW-TO-REVISE.md` | 作った後の直し方 | — |
| `FAQ.md` | よくある質問 | — |

**置き場（このフォルダの外）には次が入る。**

| 場所 | 何が入っているか | 書き換えるか |
|---|---|---|
| `<置き場>/definitions/` | 上の `definitions/` のコピー。**自分用に書き換えるのはこちら** | 書き換える |
| `<置き場>/output/` | 作ったスケジュール（HTML・JSON・CHANGELOG.md） | ここに成果物が増える |
