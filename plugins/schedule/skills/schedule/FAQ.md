# よくある質問

このツールの仕様についての質問と、その答えをまとめてあります。
**ここに載っていないことは、そのまま AI に聞いてください。**

- 直し方の詳しい手順は `HOW-TO-REVISE.md`
- 判断基準の書き換え方は `<置き場>/definitions/00-index.md`

---

## ファイルと保存

### 出来上がった HTML は何を読んでいるのか

**何も読んでいません。** スケジュールのデータも、見た目も、動きも、すべてその1ファイルの中に入っています。
外部のファイル、外部のサーバー、インターネットのどれも参照しません。
そのため、**別の場所にコピーしても、メールに添付して送っても、同じように開いて動きます。**
受け取った人の側で、置き場所を揃える必要も、何かを入れる必要もありません。

### 画面で直した内容はどこへ行くのか

**「書き出す」を押すまで、どのファイルにも残りません。**
画面の上の変更はブラウザの中だけに保持されていて、再読み込みやタブを閉じる操作をすると消えます
（消える前に確認が入ります）。
画面の上部には「変更 N 件」と出るので、残していないものがあるかどうかはそこで分かります。

### 「書き出す」と「保存」は何が違うのか

**このツールに「保存」はありません。「書き出す」しかありません。**
書き出すと、**いま画面にある内容で新しいファイルが2つ作られます**（`.html` と `.json`）。

| | 起きること |
|---|---|
| 開いているページ | **変わりません。** 元のファイルのままです |
| 新しいファイル | ブラウザのダウンロード場所に2つ出ます |
| 版数 | **1つ上がります**（`r02` なら `r03` に） |

続きを直したいときは、**新しく出たほうの HTML を開き直してください。**
古いページのまま直し続けると、次の書き出しでそれまでの変更が消えます。

### 書き出したファイルをどうすればいいか

**置き場の `output/<識別子>/` へ移してください。** 元のファイルと同じフォルダです。
「書き出したファイルを取り込んで」と AI に言えば、移動まで任せられます。

移さずにダウンロード場所へ置いたままにすると、**AI が最新版を探したときに見つけられません。**
画面で直す前の内容から作業が始まってしまうので、移すか、置いてある場所を伝えるかしてください。

### 生成したファイルはどこに保存されるか

**導入時に決めた「置き場」に保存されます。** 初めてスケジュールを作るとき、AI が保存先の候補を
1つ提示するので、そのままでよければ承認してください。決めた場所は `CLAUDE.md` に記録され、
次回以降は聞かれません。

**置き場は、このスキル本体が入っているフォルダとは別の場所です。** スキルを更新・再インストール
しても、置き場に保存したスケジュールや、自分用に書き換えた `definitions/` は影響を受けません。

### なぜ保存先のフォルダを選べないのか

**ブラウザの制約です。** ブラウザで開いているページから、パソコンの好きな場所へファイルを書くことはできません。
出せるのはダウンロード場所だけで、**同じ名前のファイルを上書きすることもできません**
（同名で出そうとすると、ブラウザが自動で「(1)」を付けます）。
版数を1つ上げる作りになっているのは、この制約を避けるためです。

### 版（r01, r02, ...）はどう増えるのか

**AI に直してもらったときと、画面から書き出したときに、1つずつ増えます。**

| 場面 | 版数 |
|---|---|
| AI に直してもらった | **+1** |
| 画面から書き出した | **+1** |
| `.json` をエディタで直接書き換えた | **上がりません。** 同じファイルを書き換えるだけです |

**古い版は消えません。** 戻したいときは、古いほうの HTML をそのまま開けば元の内容が見られます。
どの版で何を変えたかは、置き場の `output/<識別子>/CHANGELOG.md` に1行ずつ残ります。

## スケジュールの中身

### プロジェクト / フェーズ / 工程 / マイルストン / タスクの違いは

**大きいほうから5段です。**

```
プロジェクト   取り組みそのもの（別の相手・別の目的・別の始まりと終わりを持つもの）
  フェーズ     その取り組みの中の大きな括り（単体で「やる / やらない」を決められる単位）
    工程       進め方の段階（設計 / 実装 / 検証。省略できる）
      マイルストン  期日を持つ節目（「要件確定」のように、到達したかどうかを判定できる状態）
        タスク  期間を持つ最小の作業。ガントの横棒1本
```

**工程は省略できます。** 機能や対象物ごとにまとめたいとき、同じ手順を繰り返すときは、
工程を挟まずフェーズの下にマイルストンを並べます。**どちらにするかはフェーズごとに選べます。**
1つのスケジュールの中で混ざっていて構いません。

### なぜ一度に1つのフェーズしか表示されないのか

**全部を縦に並べると、増えるほど読めなくなるためです。**
画面に出るのは、選んだプロジェクトの選んだフェーズの中身だけで、残りはプルダウンで切り替えて見ます。
**1つのファイルが複数のプロジェクトを持てます。** 並行して走っている取り組みを1枚にまとめられます。

**別のフェーズにも中身はあります。** 開いた画面に見えていないだけです。
何があるかは、作ったときの報告と、プルダウンの一覧で確認できます。

### 日数はどうやって決まっているのか

**`definitions/` に書いてある基準から計算されます。**
作業ごとの標準的な工数に、規模や条件による倍率を掛け、担当する人数で割って所要日数を出します。
そのうえで、**土日と休業日を飛ばして日付が置かれます。**

基準はすべて Markdown ファイルに書いてあり、コードの中には入っていません。
実態と合わなければ、置き場にコピーされたそのファイルの数値を直してください（`<置き場>/definitions/00-index.md`）。

### 目標日に間に合わないときはどうなるのか

**間に合う計画が出ます。ただし、そのために何が必要かが必ず添えられます。**
順番は決まっていて、まず**並行にできる作業を並行にし**、次に**人を増やし**ます。

それでも届かない場合は、**間に合わない計画がそのまま出て、何日足りないかが示されます。**
数字を合わせるために予備日を削ったり、休日出勤を前提にしたりはしません。

**人を増やす前提で組まれた場合は、その人数を確保できるかを必ず確認してください。**
画面の上は間に合って見えます。

### 休みの日はどう扱われるのか。休日に作業を置きたいときは

**既定では土日と休業日には日程を置きません。** 期間の数え方も、その日は数えません。
休業日の一覧は `<置き場>/definitions/20-scheduling-rules.md` にあり、自社の休みに書き換えられます。

休日に作業を置きたいときは、2つの方法があります。

1. **依頼のときに伝える。**「本番は 11/22（日）」と言えば、その日が働く日として扱われます。
2. **画面の設定を入にする。**「休みの日にも日程を置けるようにする」を入にすると、土曜などにバーを置けます。

**2 で置いた日は、暦に「この計画では働く日」として記録され、設定を切に戻しても消えません。**
消したいときは、直前の操作を取り消すか、AI に伝えてください。

### 状態（完了・進行中）はどう変えるのか

**AI に言ってください。**「設計は終わった」「機能Aの実装に入った」で通じます。
**画面から切り替えることはできません。** 画面の役割は状態を見せることで、変えることではありません。

完了にすると、作業名に打ち消し線が入り、バーの塗りが変わります。
**上の階層の状態は自動で決まります。** 配下が全部完了すればマイルストンも完了になり、
その上の工程・フェーズ・プロジェクトも同じように追随します。

## 画面と印刷

### 印刷や PDF はできるのか

**できます。** 画面上部の「印刷 / PDF」から実行します。
**表示中のプロジェクトの、表示中のフェーズが、全部開いた状態で A4 横に収まります。**
紙にはプロジェクト名・フェーズ名・版数と、記号と色の対応表（「今日」の日付を含む）が出ます。

**画面で直した状態のまま印刷した場合は、その旨が紙に出ます。**
元データと食い違ったものが出回らないようにするためです。

### 出来上がった HTML を社外の人に渡していいか

**渡せます。** ただし**渡す前に、設定ファイルのビューを開いて2か所を確認してください。**

| 確認する項目 | なぜ |
|---|---|
| 元の依頼文 | 依頼したときの言い回しがそのまま残っています |
| 推定した前提 | 体制や社内の事情が読み取れることがあります |

どちらも画面から読めます。都合が悪ければ、AI に直してもらってから渡してください。

### 定義ファイルとは何か。どこにあるか。直すと何が変わるか

**このツールの判断基準そのものです。** `definitions/` の中の Markdown ファイル群で、
階層の決まり、日程の置き方、出力の決まり、用途ごとの標準作業・見積もり・体制が書いてあります。

**書き換えると、次に作るスケジュールから変わります。**
すでに出来上がっている資料は変わりません（どの基準で作られたかを後から追えるようにするためです）。

**書き換えるのは、置き場にコピーされた `definitions/` の中の `50-user-context.md` と `presets/` の
中身です。** スキル本体の中の `definitions/`（配布時点の既定値）を書き換えても効きません。
それ以外のファイルは書き換えない前提で作られています。詳しくは `<置き場>/definitions/00-index.md` にあります。

## できないこと

### サーバーには保存されません

**このツールにサーバーはありません。** データはすべて手元のファイルです。
どこかにアップロードされることも、外部に送られることもありません。

### 複数人で同時に編集することはできません

**1人で使う前提の作りです。** 同じファイルを2人が同時に直しても、片方の変更しか残りません。
分担したい場合は、画面の設定ファイルのビューから**表示中のフェーズだけを切り出して渡し**、
返ってきた内容を AI に取り込ませてください。

### スプレッドシートとの同期、URL での共有はできません

**どちらもサーバーが必要な機能で、このバージョンでは動きません。**
人に渡したいときは、**HTML ファイルそのものを送ってください。** 1枚で完結しているので、それで足ります。

### 進捗率は画面に出ません

**未着手 / 進行中 / 完了の3段階だけを扱います。** 「60%完了」のような数値は表示しません。
数値は、それを入力する手段とセットで初めて意味を持つためです。
