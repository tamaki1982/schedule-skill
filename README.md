# Schedule

入力文からプロジェクトのスケジュールを組み立て、**単体で開ける HTML のガントチャート**として出力する Claude Code 用のスキル。

出来上がるのは HTML ファイル 1 枚。外部を一切参照しないので、そのまま誰かに渡せば、相手はブラウザで開くだけで見られる。サーバーもインターネット接続も要らない。

```
「新機能を11月中にリリースしたい。逆算してスケジュールを作って」
```

こう伝えると、フェーズ・工程・マイルストン・タスクの階層に分解し、稼働日と休日、依存関係、バッファを踏まえた日程を組み、HTML と設定ファイル（JSON）を出力する。

---

## 導入

このリポジトリを読んでいるのが Claude Code なら、以下の手順で導入できる。**人が操作する必要がある箇所は「人がやること」と明記してある。**

### 1. マーケットプレイスの登録とインストール（人がやること）

Claude Code で次の 2 行を順に実行する。スラッシュコマンドは人が入力する必要がある。

```
/plugin marketplace add tamaki1982/schedule-skill
/plugin install schedule@schedule-skill
```

インストール後、Claude Code の再起動を求められた場合は再起動する。

### 2. 置き場所を決める（エージェントが聞く・人が答える）

初回にスケジュールを作るとき、エージェントが**生成したファイルと設定ファイルの置き場所**を確認する。候補が提示されるので、そのままでよければ承認する。別の場所にしたい場合は伝える。

決めた場所は `CLAUDE.md` に記録され、次回以降は同じ場所が使われる。

**この置き場所は、スキル本体とは別に管理される。** スキルを更新しても、作ったスケジュールや自分用に書き換えた設定は影響を受けない。

### 3. 最初の 1 本を作る

置き場所が決まったら、そのまま伝えるだけでよい。

```
「採用サイトのリニューアルを来年3月公開で計画したい」
「社内イベントを12月に開催する。準備のスケジュールを作って」
```

## 自分のやり方に合わせる

このスキルは**判断の基準をファイルに書き出してある**。書き換えれば、出てくるスケジュールが変わる。既定値のままでも動くので、合わないところだけ直せばよい。

| 直したいこと | 開くファイル |
|---|---|
| 自分の組織のやり方（稼働曜日、目標日への向き合い方、標準の作業） | `50-user-context.md` |
| 自分の分野を足す（開発・イベント・受託・制作・採用 以外） | `90-how-to-add-preset.md` |

置き場所は導入時に決めたフォルダの中にある。**直したいことをエージェントに伝えれば、該当ファイルを直してもらえる。**

## 使い方の詳細

導入後は、スキルに同梱の次の資料を参照できる。エージェントに聞けば、これらを読んで答える。

| 資料 | 内容 |
|---|---|
| `README.md` | スキル本体の案内 |
| `HOW-TO-REVISE.md` | 作ったスケジュールを直す 3 つの方法と、伝え方の実例 |
| `FAQ.md` | この道具の仕様についての質問と答え |
| `definitions/00-index.md` | 判断基準のファイル一覧と、それぞれが決めていること |
