# プリセット: 採用の進行管理

| 項目 | 値 |
|---|---|
| id | `hiring-process` |
| 表示名 | 採用の進行管理 |
| 版数 | 2.3 |
| 最終更新 | 2026/09/09 |

募集の開始から内定出しまでを、応募者の集まり方と選考の段に沿って管理する用途のためのプリセット。
簡易版として整備してある。使い込む場合は `software-development` と同じ粒度まで書き足してよい。

---

## 1. こういう依頼のときに使う

- **募集する側（人を採る側）の予定であること。** 応募する側の予定は第2章
- 「採用を始める」「募集をかける」「選考の段取りを組みたい」といった依頼
- 「説明会」「エントリー」「書類選考」「面接」「内定」といった言葉が入力文に出てくる
- 応募者が集まるのを待つ期間が日程に効いてくる
- 募集の開始から採否の通知までが範囲に入る

## 2. こういう依頼には使わない

| こういう場合 | 使うプリセット |
|---|---|
| 説明会そのものの開催が主目的で、選考は範囲に入らない | `event-campaign` |
| 採用の案内動画や記事を作ることが主目的 | `content-production` |
| 人材紹介会社から請けた選考代行で、契約・請求まで含める | `client-project` |
| **応募する側の予定**（転職活動・就職活動・求職活動） | **該当なし。** このプリセットは**募集する側**専用で、標準作業12件と役割4件がすべて募集する側のもの。立場が逆になるため読み替えが要る |

説明会を含んでいても、その後の選考と採否の通知まで管理するならこのプリセットを使う。

**「書類選考」「面接」「内定」という言葉は、応募する側の依頼にも出てくる。**
言葉ではなく**どちらの立場の予定か**で判断する。募集して選ぶ側ならこのプリセット、応募して選ばれる側なら該当しない。

---

## 3. 前提

- 応募者が集まるまでの期間は、こちらの都合で短縮できない
- 面接官は他業務との兼務であり、日程を押さえるには前もって調整が要る
- 選考結果への応募者の返答と、内定承諾の検討には、こちらが待つ期間が必要になる
- 募集媒体への掲載には、媒体側の確認の期間が入る

上記に当てはまらない案件では、該当する内容を `meta.assumptions` に書き換えて記録する。

---

## 変更時の影響

- 「こういう依頼のときに使う」を書き換えると、どの依頼でこのプリセットが選ばれるかが変わる。
- 版数を上げると、生成結果の `meta.preset.version` に記録される値が変わる。
