# 標準作業

採用の進行で繰り返し出てくる作業の型。ここに書いた内容は**生成時に参照するだけ**で、出力される JSON には作業の名前しか残らない。

## 1. 標準作業の一覧

| 標準作業 | 既定の担当役割 | 並行可否 | 増員が効くか | 説明 |
|---|---|---|---|---|
| 採用計画の策定 | 採用企画 | 直列 | 効く | 募集人数・対象・選考の段の数・判断基準を決める。ここが動くと後続すべてが動く |
| 選考基準と評価表の整備 | 採用企画 | 並行可 | 効く | 面接で何を見るかを揃える。面接官への共有もここに含む |
| 募集要項・訴求資料の作成 | 採用企画 | 並行可 | 効く | 募集要項、会社紹介、応募者向けの案内一式 |
| 説明会・面接日程の枠押さえ | 採用運営 | 直列 | **効かない** | 会場・配信枠と、面接官の予定の確保。相手の予定に依存し分担できない |
| 募集媒体への掲載準備 | 採用運営 | 並行可 | 効く | 掲載原稿の入稿、応募受付の導線の用意 |
| 媒体側の掲載審査待ち | （付けない） | 並行可 | — | 媒体側の確認の期間。縮められない待ち時間として置く |
| 説明会の実施 | 採用運営 | 直列 | **効かない** | 開催そのもの。開催日は動かせない |
| 応募の受付期間 | （付けない） | 並行可 | — | 応募者が集まるのを待つ期間。縮められない待ち時間として置く |
| 書類選考 | 採用企画 | 直列 | 効く | 応募書類の確認と通過者の絞り込み |
| 面接の実施 | 面接官 | 直列 | **そのまま効く** | 1つの段の面接を通しで実施する。面接官を増やせば1日に入る枠がそのまま増える |
| 応募者の回答待ち | （付けない） | 並行可 | — | 選考結果への返答、次の選考への出席可否、内定承諾の検討。縮められない待ち時間として置く |
| 採否の判定と通知 | 人事責任者 | 直列 | **効かない** | 合否の確定と、通知・条件提示。通知は一人ずつ行うため分担しても縮まらない |

**「増員が効かない」作業には、所要日数の計算で人数を掛けない**（`40-team.md` 第1章）。

- 説明会・面接日程の枠押さえ — 相手の予定に合わせる調整の待ちが支配的になる
- 説明会の実施 — 開催枠の数で決まり、人を足しても増えない
- 採否の判定と通知 — 一人ずつ順に行い、判断も揃える必要がある

## 2. 予備日（バッファ）

**予備日は標準作業ではない。** 遅延を吸収するための空き時間であり、作業ではないため。

| 項目 | 値 |
|---|---|
| 表し方 | `isBuffer: true` |
| 工数 | 0人日 |
| 担当役割 | 付けない |
| 名前 | 何のための予備かが分かる名前にする（例:「募集開始前バッファ」「内定出し前バッファ」） |

置く量と位置は `30-estimation.md` 第4章にある。

## 3. 作業名の付け方

**画面に出るのは作業の名前だけ**なので、名前だけで意味が通る必要がある。

| 場面 | 付け方 | 例 |
|---|---|---|
| 工程を挟む形 | 工程名が上の行に出ているので、対象を繰り返さない | 工程「選考」の下に「一次面接の実施」 |
| 工程を挟まない形 | **対象物を名前の先頭に置く** | 「技術職 書類選考」「事務職 書類選考」 |
| 同じ作業が1つのフェーズに複数出る | 何の段かで区別する | 「一次面接の実施」「最終面接の実施」 |

**標準作業の名前をそのまま使わない。** 「面接の実施」だけの行が複数並ぶと、どの段のことか分からなくなる。

---

## 変更時の影響

- 行を追加・削除すると、生成されるスケジュールに出てくる作業が増減する。**出力の形は変わらない**（標準作業は JSON に載らないため）。
- 「並行可否」を `直列` に変えると、その作業は他と重ならないように配置され、全体の期間が伸びる。
- 「増員が効くか」を「効かない」に変えると、体制を増やしてもその作業の所要日数が縮まなくなる。
- 待ち時間の3件（媒体側の掲載審査待ち / 応募の受付期間 / 応募者の回答待ち）を削ると、実態より大幅に短い日程が出る。
- 標準作業を足したら、`30-estimation.md` 第1章に標準値の行も足す。足さないと工数を推定で埋めることになる。
