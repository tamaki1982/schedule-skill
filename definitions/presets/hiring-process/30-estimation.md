# かかる日数の基準

標準作業ごとの標準工数と、それに掛ける倍率。「標準」規模の募集を基準にしている。
標準作業の一覧は `10-standard-tasks.md` にある。

## 1. 標準作業ごとの標準工数

| 標準作業 | 標準工数 | 上限側を採る条件 |
|---|---|---|
| 採用計画の策定 | 3〜5人日 | 募集職種が2つ以上ある場合 |
| 選考基準と評価表の整備 | 3〜4人日 | 面接官が5名以上いる場合。評価の目線合わせに時間がかかる |
| 募集要項・訴求資料の作成 | 5〜7人日 | 会社紹介資料を新しく作り直す場合 |
| 説明会・面接日程の枠押さえ | 2〜4人日 | 面接官が5名以上、または会場を外部から借りる場合 |
| 募集媒体への掲載準備 | 3〜5人日 | 媒体が2つ以上ある場合 |
| 媒体側の掲載審査待ち | 0人日 | 待ち時間。所要日数は第7章 |
| 説明会の実施 | 開催回数 × 1人日 | 対面と配信を併用する場合は1回あたり 2人日。**所要日数は開催回数 × 1稼働日**（第7章） |
| 応募の受付期間 | 0人日 | 待ち時間。所要日数は第7章 |
| 書類選考 | 3〜5人日 | 応募者が100名以上の場合 |
| 面接の実施 | 6〜10人日 | 応募者が50名以上、または1つの段で複数の面接官が同席する場合。**選考の段1つあたり** |
| 応募者の回答待ち | 0人日 | 待ち時間。所要日数は第7章 |
| 採否の判定と通知 | 3〜5人日 | 内定者が10名以上、または面接官の評価が割れる想定がある場合 |
| （予備日） | 0人日 | 標準作業ではない。量と位置は第4章 |

**書いてあるのは工数（人日）だけ。** 所要日数は `40-team.md` の人数と実働係数から式で出す
（`definitions/20-scheduling-rules.md` 第2章）。式を使わない作業は第7章にまとめてある。

```
有効人数 = 1 + (人数 − 1) × 0.7
所要日数 = ceil( 工数(人日) / (有効人数 × 実働係数) )
```

**面接の実施だけは人数がそのまま効く**（`10-standard-tasks.md` 第1章の「そのまま効く」）。
面接官3名なら、有効人数ではなく 3 をそのまま使う。

### 変更時の影響

- 標準工数を増やすと、その作業を含むすべてのスケジュールの期間が伸びる。
  募集開始の時期が決まっている案件では、前倒しで着手する日程が生成されるか、募集規模を削るリスク記述が増える。
- 待ち時間の3件（媒体側の掲載審査待ち / 応募の受付期間 / 応募者の回答待ち）を短くすると、
  実態より楽観的な日程が出る。ここは体制を増やしても縮まらない。

---

## 2. 規模による倍率

| 規模 | 倍率 |
|---|---|
| 小さい | 0.5 |
| 標準 | 1.0 |
| 大きい | 1.5〜2.0 |

**待ち時間の3件には規模倍率を掛けない。** 応募者側の都合で決まる期間であり、募集規模に比例しないため。
募集規模で待ちが変わる場合は、第1章の「上限側を採る条件」で扱う。

## 3. 条件による倍率

該当タスクの工数に掛ける。複数該当する場合は掛け合わせる。

| 条件 | 倍率 |
|---|---|
| 新卒採用そのものが初めて、または3年以上間が空いている | 1.4 |
| 前例のない進め方・初めて使う媒体や道具を含む | 1.3 |
| 募集職種が2つ以上ある | 1.2 |
| 選考の一部を配信で行う（対面と配信の両方を用意する） | 1.2 |

倍率を適用したタスクがある場合、そのことを `task.notes` に書き、`risks[]` にも1件記録する。

### 変更時の影響

- 倍率を上げると、その条件に当てはまる募集だけ期間が伸びる。
  特定の種類の募集で見積もりが甘いと感じたときは、標準日数ではなくこちらを調整するほうが副作用が小さい。

## 4. バッファの量

| 種類 | 量 | 置き場所 |
|---|---|---|
| 募集開始前バッファ | 3稼働日以上 | 募集準備工程のマイルストンの末尾 |
| 選考バッファ | 選考工程の経過稼働日数の 10%、最低3稼働日 | 選考工程の最後のマイルストンの末尾 |
| 内定出し前バッファ | 2稼働日以上 | 内定出し完了マイルストンの末尾 |

置き方の原則（独立したタスクとして置く、`isBuffer: true`、工数 0、担当を付けない、そのマイルストンの中に置く）は
`definitions/20-scheduling-rules.md` 第5章で共通に決まっている。
この用途のマイルストンには期日が固定された作業が入らないので、予備日はいずれもマイルストンの最後のタスクになる。
説明会の日を先に外部へ告知した場合だけ、その説明会の直前が予備日の位置になる（同 第5章）。

**募集開始前バッファを他より厚くしてある。** 掲載が遅れると応募の受付期間がそのまま後ろへ動き、
以降のすべてが連動して遅れるため。

### 変更時の影響

- 比率を上げると全体の期間が伸びる。募集開始の時期が固定の案件では、その分だけ着手日が前倒しになる。

## 5. 並行してよい組み合わせ

**この章のすべての行に、次の2つが先に効く。**

| 先に効く決まり | 内容 |
|---|---|
| **同じ役割のタスクは重ねない** | 並行してよい組み合わせであっても、担当が同じ役割なら直列に置く（`40-team.md` 第2章） |
| 同時本数の上限 | 同時に走らせられる作業本数を超えない（`40-team.md` 第2章） |

| 先に進むもの | 並行して進めてよいもの | 着手のタイミング |
|---|---|---|
| 採用計画の策定 | 選考基準と評価表の整備 | 採用計画が半分進んだ時点 |
| 募集要項・訴求資料の作成 | 募集媒体への掲載準備 | 募集要項の本文が固まった時点 |
| 募集要項・訴求資料の作成 | 説明会・面接日程の枠押さえ | 説明会の回数が決まった時点 |
| 応募の受付期間 | 書類選考 | 受付開始から半分進んだ時点。届いた分から順に見る |
| 面接の実施 | 応募者の回答待ち | 面接開始から2稼働日後 |

## 6. 直列にすべき組み合わせ

| 順序 | 理由 |
|---|---|
| 採用計画の策定 → 募集要項・訴求資料の作成 | 募集人数と対象が動くと書き直しになる |
| 選考基準と評価表の整備 → 面接の実施 | 基準が無いまま面接すると評価を揃え直すことになる |
| 媒体側の掲載審査待ち → 応募の受付期間 | 掲載されるまで応募は発生しない |
| 書類選考 → 面接の実施 → 採否の判定と通知 | 前段が終わらないと意味のある作業にならない |
| 一次の面接 → 最終の面接 | 例外を作らない |

### 変更時の影響

- 並行してよい組み合わせを増やすと期間は短くなるが、同時進行の本数が `40-team.md` の上限を超えると実行不可能な計画になる。上限とセットで見直す。
- 「応募の受付期間 ∥ 書類選考」を外すと、受付が終わってから書類選考を始める形になり、全体が2〜3週間伸びる。

**並べたあとに前後が逆転していないか確認する。**
後のタスクの開始日を先行タスクの開始日より前に置かない。

## 7. 式を使わない作業の所要日数

工数が 0 の待ち時間と、開催日が固定される作業は、式ではなく次の値をそのまま所要日数にする。

| 標準作業 | 所要日数 | 上限側を採る条件 |
|---|---|---|
| 媒体側の掲載審査待ち | 3〜5稼働日 | 媒体が2つ以上ある場合 |
| 応募の受付期間 | 20稼働日以上 | 募集人数が20名を超える場合は 30稼働日 |
| 応募者の回答待ち | 5〜10稼働日 | 内定承諾の検討では 10稼働日を採る |
| 説明会の実施 | 開催回数 × 1稼働日 | — |

**この3件の待ちは、増員でも並行化でも1日も縮まらない。**
目標日に間に合わない募集では、ここが期間の下限を決める（`definitions/20-scheduling-rules.md` 第3章 Step 5）。
**規模倍率も条件倍率も掛けない**（第2章）。

### 変更時の影響

- 応募の受付期間を短くすると全体が縮むが、応募者が集まりきらないまま選考に入る計画になる。

---

## 8. 同じ作業が繰り返し出るとき

採用では、同じ標準作業が1つのフェーズに2回以上出ることが多い（一次面接と最終面接、複数職種の書類選考など）。
**2回目以降の工数に係数を掛ける。**

| 何回目か | 工数に掛ける係数 |
|---|---|
| 1回目 | 1.0 |
| 2回目 | 0.7 |
| 3回目以降 | 0.5 |

| 決めること | 決まり |
|---|---|
| 下限 | 0.5人日を下回らない |
| 数える範囲 | **同じフェーズの中**。フェーズが変われば1回目に戻す |
| 適用しない作業 | 第7章の4件（待ち時間と説明会の実施）。回数を重ねても相手の時間は減らない |
| 記録 | 係数を適用したことを `meta.assumptions` に1行残す |

**最終面接は一次面接より軽い。** 対象人数が絞られ、評価の観点も決まっているため。
ただし対象人数が一次と同程度になる想定なら、係数を使わず個別に見積もる。

### 変更時の影響

- 係数を 1.0 に戻すと、選考の段が多い募集で期間が目に見えて伸びる。
