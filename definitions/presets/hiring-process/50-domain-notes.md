# この用途ならではの注意点

## 1. 自分たちで縮められない期間

| 何を待つか | 目安の期間 | 短縮できるか |
|---|---|---|
| 募集媒体側の掲載審査 | 3〜5稼働日 | できない。入稿を前倒しするしかない |
| 応募が集まるまでの受付期間 | 20稼働日以上 | できない。短くすると母集団が足りなくなる |
| 選考結果への応募者の返答 | 3〜5稼働日 | できない。次の選考の日程を早く提示することで実質的に詰める |
| 内定承諾の検討期間 | 10〜20稼働日 | できない。承諾期限を切っても、辞退の risk が上がるだけ |
| 面接官の予定確保 | 面接の2週間前まで | できない。枠押さえを前倒しする |

これらは待ちのタスクとして独立に置き、`assigneeRole` を付けない。**予備日ではないので `isBuffer` は立てない。**
他の作業の裏で並行させ、選考の開始日から逆算して着手日を決める。

## 2. 後ろ倒しができない日

| 何 | なぜ動かせないか |
|---|---|
| 業界で共有されている広報開始・選考開始の時期 | 遅れると他社の選考が先に進み、応募者が抜ける |
| 告知済みの説明会の開催日 | 応募者への案内が先行している |
| 入社日から逆算した内定出しの期限 | 入社準備・受け入れ体制の都合で動かせない |
| 学事日程（試験期間・長期休暇）と重なる選考 | 応募者側が参加できない |

こうした日がある場合、その直前に必ず予備日を置く。
**説明会は長期休暇の直前・直後を避ける。** 応募者が集まらず、開催回を追加することになる。

## 3. 見落としやすい作業

- 不採用者への連絡。通過者の対応だけを積んで漏らしやすい
- 面接官への評価基準の共有と目線合わせ。基準だけ作って共有を忘れる
- 応募者からの問い合わせ窓口の用意と、返信の担当決め
- 内定から入社までのつなぎとめ（懇談会、連絡の継続）
- 応募書類の取り扱いと保管期間の取り決め
- 説明会の欠席者へのフォローと、資料の後送

これらを工程テンプレートが拾えていない場合、該当する標準作業のタスクとして足す。

## 4. この用途で必ず記録するリスク

共通側（`definitions/20-scheduling-rules.md` 第9章）の条件に加えて、次を記録する。

| 状況 | 記録する内容 |
|---|---|
| 応募の受付期間が20稼働日を下回っている | 母集団が足りなくなった場合に、追加募集をどこに入れるか |
| 面接官の実働係数が 0.2 以下、または人数が2名以下 | 面接工程が延びた場合に、どの段を削るか |
| 内定承諾の検討期間が10稼働日を下回っている | 辞退が出た場合の補充枠をどこに置くか |
| 他社の選考が集中する時期と選考が重なっている | どの段で離脱が起きやすいか |
| 新卒採用そのものが初めて、または長く間が空いている（倍率1.4を適用したタスクがある） | どのタスクが該当し、進め方が想定どおりに回らなかった場合に何を落とすか |

---

## 変更時の影響

- 第1章に行を足すと、その待ち時間が独立したタスクとして計画に現れ、全体の期間が伸びる。実態に合っていれば、伸びるのが正しい。
- 第3章の項目は工程テンプレートに昇格させることもできる。頻繁に足しているものがあれば `20-structure.md` に移す。
