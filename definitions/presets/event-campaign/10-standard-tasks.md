# 標準作業

イベント・キャンペーンの運営で繰り返し出てくる作業の型。ここに書いた内容は**生成時に参照するだけ**で、出力される JSON には作業の名前しか残らない。

版 6.0 でタスク種別を削除したため、このファイルは種別の語彙表ではなく、標準作業の一覧になった。
以前の内容は `_archive/definitions/presets/event-campaign/10-task-types_v5.0_2026-09-06.md` にある。

## 1. 標準作業の一覧

| 標準作業 | 既定の担当役割 | 並行可否 | 増員が効くか | 説明 |
|---|---|---|---|---|
| 企画 | 企画 | 直列 | 効く | 内容と進め方を決める。ここが動くと後続すべてが動く |
| 確認・承認 | 企画 | 直列 | **効かない** | 関係者の合意を取る |
| 制作 | 制作 | 並行可 | 効く | 告知素材、当日資料、申込ページなどを作る |
| 告知・集客 | 運営 | 並行可 | 効く | 対象者へ届け、申込を受け付ける |
| リハーサル | 運営 | 直列 | **効かない** | 本番と同じ手順で通す |
| 当日運営 | 運営 | 直列 | **効かない** | 本番の進行と参加者対応 |
| 振り返り | 企画 | 並行可 | 効く | 結果の集計と報告 |

**「増員が効かない」作業には、所要日数の計算で人数を掛けない**（`40-team.md` 第1章）。

- 確認・承認 — 待ち時間が支配的で、人を足しても縮まない
- リハーサル — 通す時間そのものは人数で割れない
- 当日運営 — 当日の時間は固定

## 2. 予備日（バッファ）

**予備日は標準作業ではない。** 遅延を吸収するための空き時間であり、作業ではないため。

| 項目 | 値 |
|---|---|
| 表し方 | `isBuffer: true` |
| 工数 | 0人日 |
| 担当役割 | 付けない |
| 名前 | 何のための予備かが分かる名前にする（例:「制作予備日」「開催前予備日」） |

置く量と位置は `30-estimation.md` 第3章にある。

## 3. 作業名の付け方

**画面に出るのは作業の名前だけ**なので、名前だけで意味が通る必要がある。

| 場面 | 付け方 | 例 |
|---|---|---|
| 工程を挟む形 | 工程名が上の行に出ているので、対象を繰り返さない | 工程「制作」の下に「告知素材の制作」 |
| 工程を挟まない形（同じ内容を複数回やる場合） | **回次を名前の先頭に置く** | 「第1回 企画」「第1回 当日運営」 |
| 同じ作業が1つのフェーズに複数出る | 何についての作業かで区別する | 「申込ページ制作」「当日資料の制作」 |

---

## 変更時の影響

- 行を追加・削除すると、生成されるスケジュールに出てくる作業が増減する。**出力の形は変わらない**（標準作業は JSON に載らないため）。
- 「制作」を「素材制作」「ページ制作」などに割ると、担当を分けて並行させられるようになり、期間が縮む。
- 「並行可否」を `直列` に変えると、その作業は他と重ならないように配置され、全体の期間が伸びる。
- 標準作業を足したら、`30-estimation.md` 第1章に標準値の行も足す。
